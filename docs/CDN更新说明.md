# 国内订阅更新与缓存

源脚本独立于App安装包，安装新的IPA会保留已经导入的脚本。订阅清单和脚本经jsDelivr国内镜像下载时，还可能命中旧的`@main`缓存；请求中的`Cache-Control: no-cache`不能保证边缘节点已经重新取源。

2026-10-27已现场确认：GitHub源仓库三个适配器均为1.1.0，但国内CDN一度仍返回1.0.0。刷新后重新下载，91吃瓜视频、127漫画、41看片均返回1.1.0及真实图标字段。此问题不是该次IPA缺少App提交。

当前`main`发布后，GitHub Actions会对本次变更中的源脚本、订阅清单、元数据和已知旧订阅入口逐个请求CDN刷新。各CDN服务商确认成功才算通过，失败限次重试并让任务失败，不把HTTP 200或空结果当作成功。不打印源内容或用户数据。

用户安装新版App后仍看到旧源时：进入“设置 → 内容与订阅 → 一键同步全部订阅”，确认目标源版本号已更新，再重新打开列表。无需删除收藏、历史或重装App。

离线验证：`python -m unittest discover -s tools -p test_cdn_purge.py -v`。CDN提供方可能异步传播刷新，发布后仍应下载目标脚本检查版本和内容；工作流确认不等于每个用户节点已完成传播。

参考：[jsDelivr官方缓存刷新工具](https://www.jsdelivr.com/tools/purge)。
